# JoyGen 文档创建指南

在 JoyGen 平台创建文档的标准流程。

## 强制要求（必读）

**这是 doc 项目类型的核心技能，必须遵循以下规则：**

1. **必须写入文件**：文档创建完成后，必须使用 Write 工具将文档内容写入到 `public/doc.md` 文件
2. **不要只展示**：不要只在对话中展示文档内容，必须实际写入文件
3. **这是产物**：`public/doc.md` 是前端检测和渲染文档预览的唯一路径，也是用户导出到 JoySpace 的来源

## 文档输出位置

文档必须保存到以下位置：

```
public/doc.md
```

## 文档格式要求

### 基本结构

文档使用**纯 Markdown 格式**，直接以一级标题开头：

```markdown
# 文档标题

文档简介或摘要...

## 章节一

内容...

## 章节二

内容...
```

### 格式规范

1. **第一行必须是一级标题**：使用 `# 标题` 作为文档开头，这个标题会作为导出时的文档标题
2. **不要使用 YAML frontmatter**：不要在文档开头添加 `---` 包裹的元数据
3. **使用标准 Markdown 语法**：标题、列表、表格、代码块、粗体、斜体等

## 创建流程

### Step 1: 理解需求

与用户确认：
- 文档的目标和用途是什么？
- 主要读者是谁？
- 需要包含哪些核心内容？
- 是否有参考模板或格式要求？

### Step 2: 构思大纲

根据文档类型确定结构：

**技术文档**：
- 背景/问题描述
- 技术方案
- 实现细节
- 风险和限制
- 时间计划

**提案/RFC**：
- 摘要
- 动机
- 详细设计
- 替代方案
- 影响评估

**报告**：
- 执行摘要
- 主要发现
- 详细分析
- 建议和下一步

**通用文档**：
- 引言
- 正文章节
- 总结

### Step 3: 撰写内容

1. 按大纲逐节撰写
2. 使用清晰的标题层级（h1-h3）
3. 适当使用列表、表格、代码块
4. 保持段落简洁，每段聚焦一个要点

### Step 4: 保存文档

将完成的文档保存到 `public/doc.md`，保存后前端会自动检测并显示文档预览，用户可以：
- 实时预览 Markdown 渲染效果
- 点击"导出到 JoySpace"按钮将文档导出

## 示例

### 技术方案文档示例

```markdown
# 用户认证系统重构方案

从 Session 迁移到 JWT 的技术方案。

## 1. 背景

当前系统使用 Session 方式进行用户认证，存在以下问题：
- 难以支持分布式部署
- 移动端体验不佳
- Session 存储成本高

## 2. 目标

- 迁移到无状态的 JWT 认证
- 支持多端登录
- 提升系统可扩展性

## 3. 技术方案

### 3.1 JWT 结构设计

```json
{
  "sub": "user_id",
  "exp": 1234567890,
  "iat": 1234567890,
  "roles": ["user"]
}
```

### 3.2 Token 刷新策略

采用双 Token 机制：
- Access Token: 15分钟有效期
- Refresh Token: 7天有效期

## 4. 风险评估

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| Token 泄露 | 高 | 短有效期 + HTTPS |
| 并发刷新 | 中 | 分布式锁 |

## 5. 实施计划

1. 第一阶段：新接口支持 JWT
2. 第二阶段：老接口兼容
3. 第三阶段：完全迁移
```

### 会议纪要示例

```markdown
# 产品需求评审会议纪要

2024年Q1产品需求评审会议记录。

**日期**: 2024-01-15
**参会人**: 张三、李四、王五

## 会议议题

1. Q1 需求优先级排序
2. 技术可行性评估
3. 资源分配

## 讨论要点

### 需求一：用户中心改版

- **优先级**: P0
- **预估工期**: 3周
- **负责人**: 张三

### 需求二：消息推送优化

- **优先级**: P1
- **预估工期**: 2周
- **负责人**: 李四

## 决议

1. 用户中心改版优先启动
2. 消息推送放到第二迭代

## 待办事项

- [ ] 张三：完成用户中心原型设计
- [ ] 李四：调研推送方案
- [ ] 王五：协调测试资源
```

## 注意事项

1. **必须保存到 public/doc.md**：这是前端检测文档的固定路径
2. **第一行是一级标题**：作为文档标题使用
3. **不使用 frontmatter**：直接写 Markdown 内容
4. **保持内容结构清晰**：使用合适的标题层级
5. **适当使用 Markdown 特性**：列表、表格、代码块等增强可读性
6. **导出前确认内容**：用户可以在预览中查看效果后再导出
